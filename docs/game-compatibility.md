# ゲームの互換対応を増やさない方針

通常の処理は現行形式を扱う。過去の形式を無期限に受け付けるための分岐は増やさず、
必要な保存データの移行は、対象・バックアップ・検証方法を確認して一度だけ行う。
移行完了を確認してから読み取り側の互換コードを削除する。
本番データの利用状況を推測して削除・初期化しない。

## 今回削除したもの

- `GameBalance.enemy_stats()` の未使用の `relations` 引数。
  Power・達成度帯・個体差だけで計算しており、関係数は既に式に影響しない。
  呼び出し側も更新した。出題元を表す関係数の情報や現行の計算式は変えない。
- スキル交換ファイル `tanbunism.skills` のversion 1〜5の受付と、v1専用の正規化。
  現行adminの出力はversion 6であり、交換JSONはDBのセーブ形式ではない。
  古い交換ファイルは再エクスポートを必要とする。統合JSON入出力も同じ制約を使う。

`tanbunism.game-settings` のversion 1、プレイヤーの `GameSave.version = 2` は
別の形式であり、今回の廃止対象ではない。セーブ、所持品、攻略履歴は変更しない。

## 今は削除しないもの

- `state.py` の能力値の再計算、既知ダンジョンの集約、探索状況のマージ、
  所持品・育成値などを一般のスナップショット保存で上書きさせない保護。
  これらは現行の設定変更・部分保存・不正操作防止に必要で、旧形式専用ではない。
- `enemyHp` / `enemyMaxHp`、専門分野の `skill` / `skillUsed` と対応するAPI。
  現行Webコードにも参照がある。新規の遭遇がCTBであっても、未使用とは断定しない。
- 非CTBの進行中戦闘、装備の旧保存、旧ボス補正、保存済みスキル・トリガー等の復元。
  本番に該当データが残っていないことを今回確認していない。

これらの削除には、実際の保存データの読み取り調査と、必要なら一回限りの移行を先に行う。
古いというコメントだけを根拠に削除せず、互換処理を別ファイルへ移して温存するだけの
整理もしない。今回、本番DBへの読み書きやフロントエンドの変更は行っていない。

## 読み取り専用の棚卸し

一回限りの集計には `scripts/audit_game_compatibility.py` を使う。
アプリの `read_state()` / `get_game_catalog()` / `get_game_balance()` を呼ばない。
取得APIでも移行が走る経路があるため、通常のAPIレスポンスから保存形式を判断しない。

既存の接続方法で本番DBに接続できる環境から、確認済みのホストを明示して実行する。
DB設定はその環境の `NEO4J_URL` を使う。リポジトリの `.envrc` は変更せず、
URL・パスワード・トークンをチャットやコマンド履歴へ貼らない。

```sh
python scripts/audit_game_compatibility.py --expect-host CONFIRMED_DB_HOST --database neo4j
```

- 確認したRenderサービス・環境・DB名と接続先が一致することを実行前に確認する。
  このリポジトリの通常のDB接続先はテスト用のlocalhostなので、本番の結果と混同しない。
- `NEO4J_URL` に認証が含まれない場合のみ `NEO4J_USER` / `NEO4J_PASSWORD` を使える。
- 固定した `MATCH ... RETURN` で生JSONだけを読み、少量ずつストリーミングする。
  正常終了でもrollbackし、アプリの復元・正規化・移行・保存処理は通さない。
- `READ_ACCESS` はルーティング指定であって書込禁止権限ではない。
  固定queryと非commitを守り、利用できる場合はDB側の読み取り専用ユーザーを使う。
  [ドライバーのアクセスモード仕様](https://github.com/neo4j/neo4j-python-driver/blob/5.28.1/docs/source/api.rst)
  も参照。利用中の5.28.1でセッションとトランザクションAPIを確認している。
- 出力は固定名の件数のみ。ユーザーID・メール・リソース名・JSON本文・接続先・
  認証情報は表示・ファイル保存しない。例外の本文も出力しない。
- `*_users` はユーザー数、`*_objects` は保存内のオブジェクト数。
  同一スキルが複数箇所に保存されていればオブジェクト数は重複を含む。
  `legacy_equipment_users` は所持数0の旧装備参照も含み、
  `legacy_equipped_users` はそのうち現在所持しているもの。
  `battle_phase_without_marker` は戦闘マーカーなしで戦闘中の保存を数える。
- 終了コード0は読み取り集計完了、1は壊れたJSON・不明構造・未確認の保存版を含む、
  2は接続等で未完了。`complete: true` でも互換コードの削除可否を自動決定しない。
  監査中にもゲームは更新され得るため、旧形式を書き込む経路の有無も確認する。

実行時の対象環境・時刻と件数を確認してから削除を判断する。集計だけでデータの
移行・初期化・修復を実行しない。テストはローカルだけで実行し、本番でpytestを
起動しない（このプロジェクトのテストはDBを全消去する）。

アプリや管理APIには組み込んでいない。配備のためだけのデプロイも必要ない。
Render CLIが未ログイン等で本番に接続できない場合、集計結果は「未確認」のままとする。
