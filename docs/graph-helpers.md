# 共通グラフ処理の契約

`tanbun.feature.domain.graph`の関数は、可変のNetworkXグラフでも呼び出せる。
グラフをキーにしたプロセス全体のキャッシュは使わない。辺の追加・削除・属性変更が
次の呼び出しに反映され、返却したリストや辞書を利用側が変更しても後の結果に混ざらない。

## 走査

- `to_nodes(g, start, accessor)`は開始点を含む到達点を、深さ優先の初出順で一度ずつ返す。
  循環や合流があっても同じ点を再訪しない。`None`など走査処理の戻り値は混入しない。
- `to_nested(g, start, accessor)`は開始点の子から入れ子の辞書を作る。
  合流先は各枝に独立して展開する。経路上の循環は`GraphCycleError`で拒否し、
  葉に見せかけて切り捨てない。到達しない場所の循環はこの変換に関係しない。
- どちらも明示的なスタックで走査し、深さに比例してPythonの再帰スタックを消費しない。
  入れ子の出力量自体は経路数に応じて増えるため、巨大なDAGの展開が常に軽量になるわけではない。
- `accessor`が参照する関係だけを辿る。存在しない開始点の扱いは`accessor`に従う。

## キャッシュの境界

`SysNet`は解析時点のスナップショットとして扱う。親テーブルは`SysNet.parents`で
インスタンス内に保持し、単文ごとの親取得で全体を再計算しない。
内容を変更する場合は既存インスタンスのグラフを変更せず、新しい`SysNet`を作る。
可変グラフを直接調べる場合は、キャッシュしない`parent_lookup(g)`を使う。

詳細取得は型別のaccessorで直接辿り、単文ごとに全グラフのコピーを作らない。
型別サブグラフも入力グラフをキーにキャッシュしない。既存の誘導部分グラフという意味は変更しない。
見出し取得とリソース統計のグラフ照会も、入力グラフや`SysNet`をプロセス全体へ保持しない。

解析結果や用語辞書など、共通グラフ処理以外の上限・返却値の所有権は
[キャッシュ方針](cache-policy.md)を参照。すべてのfactoryを一律に変更するわけではない。
